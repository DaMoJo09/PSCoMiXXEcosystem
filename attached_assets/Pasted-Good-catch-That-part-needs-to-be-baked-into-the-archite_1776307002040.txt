# REPLIT BRIEF

## For CoMiXX + Streaming + LMS

**Project Title:**
MADMIXEDMEDIA Ecosystem Core Apps Integration Build
(CoMiXX + Streaming + LMS)

**Objective:**
Transform CoMiXX, Streaming, and LMS into a unified ecosystem that works as both:

1. web-based school-safe tools
2. desktop-launchable apps through MMM Hub

These apps must share:

* authentication
* user identity
* project ownership
* XP/progression
* workforce readiness data
* publish flows
* school-safe controls
* app-to-app navigation and handoff

---

## CORE PRODUCT DIRECTION

This is not just a group of separate web apps.

This is one ecosystem with different specialized applications:

* **CoMiXX** = core creation app
* **Streaming** = publishing, showcase, discovery, engagement, creator proof-of-work
* **LMS** = curriculum, assignments, teacher dashboards, credential tracking

Each app must feel like part of one platform and must include ecosystem navigation.

---

## GLOBAL REQUIREMENTS

### 1. Shared Ecosystem Navigation

In every app, create a persistent ecosystem nav/header/menu with buttons for:

* Hub
* CoMiXX
* FX Studio
* Streaming
* LMS
* Profile / XP / Projects

Behavior:

* In desktop mode, buttons should call deep-link routes for installed apps
* In web mode, buttons should use browser routes/URLs
* If destination app is not installed in desktop mode, redirect to MMM Hub install screen or download prompt

---

### 2. Shared Authentication

Implement one shared authentication/session architecture across:

* CoMiXX
* Streaming
* LMS
* FX Studio
* MMM Hub

Requirements:

* single sign-on
* shared user profile
* shared subscription/access tier
* shared XP profile
* shared portfolio/work history
* shared school/teacher/student role handling

User roles should support:

* student
* teacher
* school admin
* independent creator
* workforce creator
* ecosystem admin

---

### 3. School-Safe Mode

This must be a system-level feature, not just a UI toggle.

Create a **School Safe Mode** profile that can be enabled:

* per school
* per class
* per teacher
* per student account type
* per organization

School Safe Mode requirements:

* disable or restrict public messaging/chat unless explicitly enabled
* disable or restrict mature or unsafe content categories
* restrict marketplace access unless approved
* restrict external publishing destinations unless approved
* restrict public creator profile visibility where needed
* restrict remix/collab to teacher-approved or organization-approved environments
* require moderated publishing flow for student work
* allow teachers/admins to approve content before Streaming publication
* support FERPA/COPPA-ready account logic and school-controlled visibility settings
* allow separate school-safe asset packs, templates, and prompts
* disable external user-to-student contact vectors by default
* log moderation and approval actions for admin review

Add configuration layers:

* district-level policy
* school-level policy
* classroom-level policy
* user-level exceptions

---

### 4. XP + Workforce Pipeline System

Build the XP system as a cross-ecosystem identity and workforce signal.

XP is not just gamification.
XP must support:

* learning progress
* tool usage
* published output
* collaboration
* teacher validation
* portfolio development
* workforce readiness
* verified paid-work eligibility

Create an **XP and Workforce Engine** with:

#### XP Sources

* time in app
* lesson completion
* assignment completion
* save/export actions
* content publishing
* approved submissions
* remix/collaboration actions
* teacher verification
* badge/certification completion
* challenge participation
* client/project completion
* external app sync events

#### Workforce Signals

Track structured data for:

* completed projects
* project type
* tools used
* level of independence
* teacher-reviewed work
* published work
* team participation
* deadlines met
* revision cycles completed
* real-world production participation
* paid contract participation
* internship/apprenticeship readiness

Create a **Skill Passport / Workforce Profile** that includes:

* XP total
* XP by skill category
* verified competencies
* tool proficiency
* published works
* teacher endorsements
* admin endorsements
* workforce eligibility flags
* contract readiness tier
* internal MMM creator eligibility
* outside-partner readiness data

---

### 5. Outside-App XP Sync / External Data Intake

The XP system must be open to receiving verified activity data from outside apps.

Create an **External XP Ingestion API**.

Requirements:

* secure authenticated API/webhook endpoint
* accepts structured activity payloads from approved external apps
* supports source verification and API keys
* supports deduplication to prevent duplicate XP awards
* supports event logging and audit history
* supports moderation/review for high-impact XP events
* supports mapping external actions into internal XP categories

Payload structure should support:

* external app name
* external app user identifier
* mapped ecosystem user identifier
* event type
* event timestamp
* duration if applicable
* asset/project ID if applicable
* action category
* skill category
* raw score/value
* verification level
* metadata blob

Examples of external sync sources:

* FX Studio
* future desktop tools
* partner tools
* third-party creative tools
* internal production tools
* outside certification systems

Create rules engine support for:

* award XP automatically
* hold XP pending review
* deny XP if source unverified
* translate external skill events into workforce indicators

Also support:

* inbound portfolio/project metadata
* inbound certification completion events
* inbound usage metrics for approved partner apps
