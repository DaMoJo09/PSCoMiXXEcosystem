# PART 1: MASTER PRODUCT VISION

We are building a **unified creative ecosystem**, not a collection of disconnected web apps.

The ecosystem should ultimately function like a **Maxon / Reallusion-style software suite**, where:

* the **MADMIXEDMEDIA website** tells the story and acts as the public-facing front door
* users can **download MMM Hub**
* MMM Hub acts as the launcher, updater, login shell, and ecosystem controller
* users can install/open:

  * **CoMiXX**
  * **FX Studio**
  * **Streaming**
  * **LMS**
  * future apps
* each app can launch or send assets/data to the others
* each app shares:

  * auth
  * user identity
  * project ownership
  * asset pipeline
  * XP
  * workforce readiness
  * school-safe rules
  * publish and portfolio data

Even before MMM Hub is built, all apps should behave **as if they are already one ecosystem**.

This means:

* shared branding
* shared navigation
* shared auth
* shared data model
* shared asset movement
* shared XP/workforce pipeline
* school-safe mode
* desktop-launch readiness
* web fallback support

# PART 2: CORE ECOSYSTEM RULES

## Rule 1: One Ecosystem

CoMiXX, HOPs, FX Studio, Streaming, and LMS must not feel like separate products. They are specialized surfaces inside one ecosystem.

## Rule 2: Shared Navigation

Every app must include ecosystem navigation/buttons for:

* Hub
* CoMiXX
* FX Studio
* Streaming
* LMS
* Profile / XP / Projects / Portfolio

Behavior:

* in desktop mode, these should trigger deep links or installed-app launch logic
* in web mode, these should route to URLs or web app views
* if the target app is not installed in desktop mode, prompt install via Hub or open web fallback

## Rule 3: Shared Auth

There must be one shared authentication/session model across the ecosystem:

* single sign-on
* shared user profile
* shared subscriptions/access tier
* shared XP profile
* shared workforce profile
* shared portfolio/publishing history
* shared school/organization context

## Rule 4: School-Safe by Design

School-safe behavior must be built into the system at the data, permission, moderation, and publishing levels, not just as a UI setting.

## Rule 5: XP Must Mean Workforce

XP is not just gamification. It must support:

* learning progression
* verified skills
* portfolio growth
* teacher validation
* publication milestones
* workforce readiness
* contract and opportunity eligibility

## Rule 6: Outside Apps Must Be Able to Sync XP

The ecosystem must support secure intake of XP and work data from outside apps and future tools through authenticated APIs/webhooks.

## Rule 7: Everything Created Anywhere Can Feed Everywhere

All graphic modes and outputs should feed a shared ecosystem asset pipeline, so anything created in one mode can be reused in others.

# PART 3: SCHOOL-SAFE SYSTEM REQUIREMENTS

Build a **School Safe Mode** system that can be applied:

* per district
* per school
* per classroom/course
* per teacher/admin
* per student/user role
* per organization profile

## School Safe Mode must support:

* moderated publishing flow for student work
* approval before public publication
* optional private/classroom-only publishing
* restricted or disabled public messaging/contact
* restricted or disabled public remix/collaboration unless approved
* restricted asset categories where needed
* approved school-safe asset packs and templates
* restricted marketplace access where needed
* restricted public creator profile exposure
* role-based external sharing/export controls
* admin and teacher audit visibility
* COPPA/FERPA-oriented behavior and visibility logic
* school-managed identity and permissions

## Policy hierarchy:

* district-level policy
* school-level policy
* classroom-level policy
* user-level overrides where appropriate

All app-to-app payloads must carry relevant school-safe flags and policy context.

# PART 6: HOPs MASTER PRODUCT DEFINITION

HOPs is not just one playback trick. It is a **short-form visual storytelling system** with multiple playback modes.

## HOPs must support 3 core playback modes:

### 1. Still Frame Mode

A composed fixed-frame scene.
Can be:

* static
* subtly animated
* ambient
* poster-like
* breathing comic panel
* title card scene

Should support:

* layered compositions
* imported assets
* motion FX overlays
* subtle animation
* export as PNG and GIF

### 2. Pan Mode

This is the Roku City-inspired drifting world mode.

Should support:

* wide horizontal stitched canvas
* looping panoramic world
* camera drift/pan
* variable speed
* seamless looping
* parallax layers
* optional moving live elements
* imported FX Studio assets
* PNG poster export
* GIF excerpt export

### 3. Video Mode

A regular framed motion mode.

Should support:

* fixed viewport
* scene/shot playback
* timeline-based sequencing
* cuts/fades/simple transitions
* imported assets and motion elements
* export as GIF and later video formats

## Product framing:

HOPs should allow creators to tell short-form visual stories in three ways:

* **Still**
* **Pan**
* **Video**

Do not make these separate unrelated tools. They should be playback modes inside one HOPs system.

# PART 7: HOPs STITCH MODE / ROKU CITY EXECUTION

Inside HOPs, especially for Pan Mode, create a **Stitch Mode**.

## Stitch Mode

Purpose:
Build one long panoramic visual world from multiple images/assets.

## Stitch Mode requirements:

* import images from device
* import images from asset library
* pull in assets from FX Studio / CoMiXX outputs
* place images end-to-end on a horizontal cutting-floor style canvas
* reorder segments
* snap edges together
* support overlap/blending at seams if possible
* support cropping and transform controls
* support extremely wide panoramic compositions
* output to a pan-ready world canvas

## Pan Mode playback requirements:

* camera pans through stitched scene
* adjustable scroll speed
* reverse direction option
* loop toggle
* start/end offset controls
* smooth/cinematic motion options
* seamless looping if configured

## Parallax system requirements:

Each layer should support:

* depth
* speed multiplier
* independent motion settings

Example:

* sky = slowest
* distant background = slow
* buildings = medium
* foreground = fast

## Live animated elements in Pan Mode:

Allow individual placed assets to:

* move independently
* loop movement
* follow simple paths
* repeat across timeline/world
* act like cars, birds, lights, characters, etc.

This should be phased:

* first basic stitch + pan
* then parallax
* then live looping element motion

# PART 16: NON-NEGOTIABLE PRODUCT PRINCIPLES

1. Do not build any part of this as a disconnected one-off.
2. Do not build school-safe mode as cosmetic only.
3. Do not treat XP as meaningless gamification.
4. Do not silo assets by mode.
5. Do not make HOPs only one playback style.
6. Do not build browser-only assumptions into routing and handoff.
7. Build now for web use, but structure everything for desktop suite behavior later.
